SheetsService: required API (implementation details)

Create src/services/sheetsService.ts. It must:

Authenticate using the Google Service Account credentials from env var GOOGLE_SERVICE_ACCOUNT_CREDENTIALS (the full JSON, base64-encoded is acceptable).

Expose the following async functions:

getRows(sheetName: string, options?: { filters?: Filter[], columns?: string[], ranges?: string[] }) — should support batchGet for multiple sheets + simple in-memory filtering (do not attempt SQL-like joins inside Sheets API).

getRowByPK(sheetName: string, pkField: string, pkValue: string) — locate the row index and return an object mapping columns to values.

appendRow(sheetName: string, rowObject: Record<string, any>) — append single row and return the generated ID + row position. Use spreadsheets.values.append.

batchAppend(sheetName: string, rows: Record<string, any>[]) — append many rows in a single API call. Use spreadsheets.values.append with resource.values = [ [r1col1, r1col2…], [r2col1, ...] ] or spreadsheets.values.batchUpdate when updating multiple ranges; prefer append with multiple rows for same-sheet bulk writes.

updateRow(sheetName: string, pkField: string, pkValue: string, patch: Record<string, any>) — find row index by PK and update the exact row range using spreadsheets.values.update.

Implement efficient operations:

Use spreadsheets.values.batchGet to read multiple sheets in one HTTP call.

For append operations, use valueInputOption: 'RAW' and insertDataOption: 'INSERT_ROWS' and set includeValuesInResponse: false (or true if you need the appended values).

For getRowByPK, implement a clean utility that:

Fetches the header row and maps header -> column index.

Fetches the sheet rows and find the row index where row[pkColIndex] === pkValue.

To update, compute the A1 range for that row (e.g., Members!A${rowIndex + 1}:Z${rowIndex + 1}) and call values.update.

Add retries and exponential backoff for Google API errors (quota/rate limit handling). Use a small number of retries (3) with incremental delays.

Important: Keep the SheetsService thin and predictable so the service layer above it can implement business rules and transactions (no business logic in the SheetsService).

ID generation rule

Use the uuid package and generate IDs with a short prefix: e.g. MEM-${uuidv4()}, ATT-${uuidv4()}, FAM-${uuidv4()}. This assures uniqueness without sequence coordination.

Authentication & Authorization

Implement POST /api/v1/auth/login to authenticate staff accounts: verify password (if stored in Sheets, passwords must be hashed — use bcrypt). Prefer storing staff credentials in a dedicated secure store; if kept in Sheets, enforce that passwords are pre-hashed and never store plain text. If the docs do not specify, ask the human to provide a secure credentials plan.

On login, issue JWT (HS256) with JWT_SECRET. Token payload: { sub: memberId, permissions: string[], iat, exp }. Use exp with reasonable lifetime (e.g., 8 hours).

Implement middleware auth.ts to verify token and permit(permission) to gate routes based on staff permissions read from StaffPermissions sheet. Put permissions into the token at login time for efficiency. Validate that permission checks read from token and fall back to StaffPermissions read when needed.

Cross-cutting implementation & security rules (must be enforced)

Use helmet(), express-rate-limit() (configurable per route), and cors() (restrict to frontend origins).

Data validation: use zod or joi schema validators for all incoming requests. Respond with 400 and a clear error body { error: string, details?: any }.

Never log full service account keys, JWT secrets, or phone numbers in plaintext logs.

Send minimal fields in responses; e.g., do NOT return salary or other sensitive fields unless the caller has explicit permission. If storing sensitive fields (salary), encrypt them at rest using an env-key SENSITIVE_DATA_KEY and document how to decrypt it. Ask human before implementing salary encryption approach.

Expose X-Request-Id header for tracing requests; log it.

How to create & use the Google service account JSON (instructions for the human)

In Google Cloud Console:

Create/select a project.

Enable Google Sheets API and Google Drive API for the project.

Go to IAM & Admin → Service Accounts → Create Service Account (name = churchflow-backend-sa).

Grant it the "Editor" role (or minimal roles required for Sheets access).

Create a JSON key (select JSON). Download the file service-account.json.

Share the Google Sheet with the service account email (the service account has an email like churchflow-backend-sa@project-id.iam.gserviceaccount.com) — give Editor permission.

On your development machine:

(macOS / Linux) cat service-account.json | base64 -w 0 — copy the output string.

(Windows PowerShell) Get-Content service-account.json -Raw | Out-File -Encoding ascii -Width 2147483647 <temporaryfile> then certutil -encodehex service-account.json service-account.b64 0x40000000 (or instruct to use WSL). Simpler: instruct user to upload the file to their secret manager or use WSL.

In .env (development) or your hosting secret manager set GOOGLE_SERVICE_ACCOUNT_CREDENTIALS to the raw JSON or the base64 string depending on implementation preference. If you pass base64, the backend must decode it at runtime:

const saJson = JSON.parse(Buffer.from(process.env.GOOGLE_SERVICE_ACCOUNT_CREDENTIALS, 'base64').toString('utf8'));
const auth = new google.auth.JWT({
  email: saJson.client_email,
  key: saJson.private_key,
  scopes: ['https://www.googleapis.com/auth/spreadsheets', 'https://www.googleapis.com/auth/drive'],
});


Set GOOGLE_SHEET_ID to 1XCqJk2XBPcPjXFo1nN-h4tWMLLOrAJnajfT63rQ3iDs (the provided sheet ID) in .env.

How to do batch writes and best practices (instructions AI must follow)

For attendance and other high-volume writes, use single-call bulk append:

Prepare rows as an array of arrays where each inner array maps to sheet column order (use header mapping).

Use spreadsheets.values.append with:

await sheets.spreadsheets.values.append({
  spreadsheetId,
  range: `${sheetName}!A:Z`,           // or the precise header range
  valueInputOption: 'RAW',
  insertDataOption: 'INSERT_ROWS',
  resource: { values: rows },         // rows: [ [col1, col2, ...], [ ... ] ]
});


For multi-sheet reads, use spreadsheets.values.batchGet({ spreadsheetId, ranges: ['Members!A:Z','Families!A:Z'] }).

For idempotency:

On POST /attendance/check-in, first getRows('Attendance', { filters: [ { field: 'GatheringID', op: '=', value: gatheringId } ] }) and compute which memberIds are missing; only append new rows for missing memberIds. This minimizes duplicates.

For concurrency & rate limiting:

Implement request-level locks or semaphores for huge bursts (or use a queuing mechanism). For a simple solution, use optimistic append: read existing rows, compute new rows, append; if append fails due to quota, retry with backoff.
